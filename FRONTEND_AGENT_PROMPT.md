Ты frontend-агент проекта.  
Нужно реализовать **только этап №{{3}}** из `FRONTEND_PLAN.md`.

## 1. Область ответственности
- Разрешено изменять только:
  - `frontend/**`
- Запрещено изменять:
  - `backend/**`
  - `neo4j/**`
  - файлы вне выбранного этапа.

## 2. Обязательная последовательность действий
1. Открой `FRONTEND_PLAN.md`.
2. Найди строку этапа №{{3}}.
3. Выпиши:
  - название этапа;
  - вход этапа;
  - выход этапа;
  - точное название коммита.
4. Убедись, что реализация ограничена только этим этапом.
5. Реализуй код.
6. Запусти релевантные проверки.
7. Сверь фактический результат с выходом этапа.
8. Сделай commit с точным названием из плана.
9. Подготовь краткий отчёт по шаблону ниже.

## 3. Архитектурные и качественные требования
- Соблюдать SOLID/GRASP на уровне frontend-модулей.
- Компоненты не содержат бизнес-логики API.
- API-запросы только через typed service/hooks слой.
- Runtime-валидация контрактов обязательна (`zod`).
- Обязательно сохранять синхронизацию с backend-контрактами.
- Каждый endpoint должен иметь явный UI-flow.
- Запрещены скрытые интерфейсы и неиспользуемые API вызовы.

## 4. Ограничения выполнения
- Не переходить к следующему этапу.
- Не менять commit message.
- Не оставлять частично подключённые UI-экраны.
- Не добавлять фичи вне вход/выход выбранного этапа.

## 5. Проверки перед коммитом
- Минимально обязательные:
  - сборка/запуск приложения;
  - тесты и линтеры в затронутой области;
  - ручная проверка пользовательского сценария этапа.
- Проверить, что endpoint-ы этапа реально отображены в UI и доступны пользователю.
- Если что-то не удалось запустить, указать в отчёте.

## 6. Формат финального отчёта (обязательно)
Ответ должен быть кратким и содержать:
1. `Этап`: №{{3}} и название.
2. `Реализовано`: что сделано по факту.
3. `Проверки`: что запущено и результат.
4. `Сверка с планом`:
  - вход совпал/не совпал;
  - выход совпал/не совпал.
5. `Нюансы и риски`: отклонения, ограничения, что осталось.
6. `Коммит`: SHA и точное название.
